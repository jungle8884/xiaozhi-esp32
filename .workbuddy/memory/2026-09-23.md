## xiaozhi-esp32-server（服务端）代码讲解

用户要求讲解服务端代码。本地路径：`D:\CODE\TEST\ESP32\xiaozhi-esp32-server`
用户 fork：git@github.com:jungle8884/xiaozhi-esp32-server.git，main 分支，HEAD bc2fc35

### 三模块架构
| 模块 | 语言 | 端口 | 作用 |
|---|---|---|---|
| `main/xiaozhi-server` | Python (asyncio) | 8000 WS / 8003 HTTP | **核心**：设备接入、ASR/LLM/TTS 编排 |
| `main/manager-api` | Java SpringBoot（artifactId: xiaozhi-esp32-api） | 8002 | 智控台后端，MySQL+Redis |
| `main/manager-web` | Vue | 8002 | 智控台前端 |

### Python 核心文件职责
- `app.py` → 入口，起两个 asyncio task：WebSocketServer(8000) + SimpleHttpServer(8003 OTA)
- `core/websocket_server.py` → 每连接创建独立 ConnectionHandler；`_http_response` 区分 WS upgrade 与普通 HTTP；`update_config()` 支持热更新模块
- `core/connection.py`(1027行) → **核心**。handle_connection 认证→发 welcome_msg→异步初始化组件→收消息；`_route_message` 按 str/bytes 分流；`chat()` 是 LLM 流式→TTS 队列的主循环
- `core/handle/textHandle.py` → JSON 文本消息路由：hello / abort / listen / iot / mcp
- `core/handle/receiveAudioHandle.py` → VAD 判定→ASR→意图识别→startToChat
- `core/api/ota_handler.py` → OTA 接口，下发 websocket 地址
- `core/auth.py` → AuthMiddleware，token / MAC 白名单

### providers（可插拔适配器）
- ASR: aliyun/baidu/doubao/fun_local/fun_server/sherpa_onnx_local/tencent
- LLM: openai/AliBL/ollama/dify/coze/gemini/xinference/homeassistant
- TTS: edge(免费)/aliyun/doubao/cozecn/gptsovits/huoshan_double_stream/minimax/siliconflow...
- VAD: silero（默认）
- Intent: nointent / intent_llm / function_call
- Memory: nomem（默认）/ mem_local_short / mem0ai

### 配置优先级（重要）
`data/.config.yaml` **覆盖** `config.yaml`。若启用智控台（read_config_from_api=true），则 config.yaml 全部失效，走智控台下发。
config.yaml 关键段：server(8000/8003)、selected_module、prompt、wakeup_words、plugins、close_connection_no_voice_time(120s)、xiaozhi(opus/16000/60ms)

### 部署方式
- `docker-compose.yml`（单 server）/ `docker-compose_all.yml`（server+web+mysql+redis 全家桶，web 8002）
- requirements.txt 含 torch+funasr（本地 ASR 模型较大）；FFmpeg 必装（check_ffmpeg_installed）
- 视觉接口 `/mcp/vision/explain`

## 自研 AIoT 平台：小智 AI 控制 FastBee 物联网设备（方案分析）

用户目标：搭建小智AI语音 → 控制 FastBee 平台下某个用户的物联网设备。

### FastBee 源码位置与结构
本地：`D:\CODE\TEST\fastbee-open`
- `wumei-smart/springboot` → Java SpringBoot 后端（模块化：fastbee-admin/common/framework/gateway/open-api/plugs/iot/server）
- `wumei-smart/vue` → 管理前端
- `fastbee-app` → uniapp 移动端

### 【关键发现】FastBee 有独立对外 OpenAPI 模块 `fastbee-open-api`
`com.fastbee.data.controller.*`，暴露设备管理/物模型/运行数据的 REST 接口。

**设备控制核心接口（集成接入点）**：
```
POST /iot/runtime/service/invoke     ← 服务下发（控制设备）
权限: @PreAuthorize("@ss.hasPermi('iot:service:invoke')")
Body (InvokeReqDto):
{
  "serialNumber": "860061060282358",  // 设备编号（必填）
  "productId": 2,                      // 产品ID（必填）
  "identifier": "temp",                // 物模型标识符（必填）
  "type": 1,                           // 物模型类型（必填）
  "isShadow": false,                   // 是否影子模式（必填）
  "remoteCommand": {"4": "4"},         // 寄存器地址→值（modbus）
  "timeOut": 10
}
返回: AjaxResult.success(messageId)
```
**物模型类型** `ThingsModelType.getType(type)`：1=属性 2=功能/服务 3=事件
**属性/状态查询**：`GET /iot/runtime/runState?serialNumber=&type=&productId=`
**下发回执查询**：`GET /iot/runtime/fun/get?serialNumber=&messageId=`（当前是 TODO 空实现）

### 【关键发现】认证机制
- `SecurityConfig`（fastbee-framework）：`/login` `/register` `/captchaImage` `/iot/tool/**` `/wechat/**` 等 permitAll，**其余接口全部需要 JWT token**
- 登录：`SysLoginController`（fastbee-admin），RuoYi 风格 `/login` 返回 token
- `@ss.hasPermi('xxx')` = Spring Security 权限表达式，**必须用有对应权限的账号，普通用户会 403**
- 原生支持 OAuth2（`OauthClientDetailsController` + `sys_oauth_client_details` 表），第三方接入走 OAuth2 client_credentials 更规范
- 原生支持 API Key（`ProductAuthorizeController`）

### MQTT 下发链路（FastBee 内部）
`IMqttMessagePublish`(fastbee-mq) → `MqttMessagePublishImpl`(fastbee-server/mqtt-broker) → 发布到设备订阅主题
`IFunctionInvoke.invokeNoReply(reqDto)` 是服务层入口

### 三条集成路线（已分析）
| 路线 | 做法 | 评价 |
|---|---|---|
| A. HTTP 中间件（推荐 MVP） | 小智服务端 MCP 工具 → requests → FastBee OpenAPI | 零侵入、1~2 天可通、解耦 |
| B. Java MCP 服务 | SpringBoot 暴露 MCP tool，xiaozhi-server 走 mcp_server_settings.json | 复用 Java 栈，更企业化 |
| C. 直接改 FastBee | 加 Controller + 调 IFunctionInvoke | 性能最好，侵入大、升级麻烦 |

### 权限/多租户风险
FastBee 是 RuoYi 多租户体系，`@ss.hasPermi` 校验的是**当前登录用户**权限。要控制「某一个用户的设备」，需该用户 token 或专开具备 `iot:service:invoke` 的服务账号。必须提前确认的合规点。
