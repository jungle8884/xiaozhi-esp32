## Docker 全模块部署方案复核（SOP vs 官方 Deployment_all.md）

结论：**不用上传源码/不用编译，官方镜像已含 Python 服务端 + manager-api + manager-web 构建产物。**
上传物仅 3 项：`docker-compose_all.yml`、`data/.config.yaml`、`models/SenseVoiceSmall/model.pt`（936MB）。

### SOP 里两处会导致失败的地方（待用户确认后修正）
1. **`.config.yaml` 的 `manager-api.url`**：SOP 复用了本地那份（`http://127.0.0.1:8002/xiaozhi`），
   在容器里 `127.0.0.1` 指向容器自身 → 连不上 manager-api。
   官方要求改成容器名：`http://xiaozhi-esp32-server-web:8002/xiaozhi`。
2. **设备 OTA 端点选了 8003**（SOP 第七步写 `http://服务器IP:8003/xiaozhi/ota/`）：
   - 8003 的 Python OTA 只下发 ws 地址，**不生成激活码** → 设备绑定时播报"没有找到该设备的版本信息"
   - 且官方镜像**没有** `config_loader.py` 透传 websocket 的补丁 → 该路径下 `server.websocket` 会被丢弃
     → OTA 下发空 URL → 设备报 `Invalid URI format`
   → 应改为走 **8002**：`http://服务器IP:8002/xiaozhi/ota/`，并在智控台【参数管理】填
   `server.websocket` = `ws://IP:8000/xiaozhi/v1/`、`server.ota` = `http://IP:8002/xiaozhi/ota/`

### 镜像里没有的本地补丁（部署后需确认）
- `edge.py` TTS v2 端点 → 若镜像内 edge_tts 版本旧，TTS 会 403
- `config_loader.py` / `ota_handler.py` / `http_server.py` 的 websocket 空值修复 → 走 8002 可规避
- 规避方案：自己在服务器上 build 镜像（把本地代码 COPY 进去），代价是要传源码

### 其他要点
- MySQL 数据靠 `./mysql/data` 卷持久化；Redis 无卷（激活码会丢，但绑定关系在 MySQL 里）
- 安全组放行 8000 / 8002 / 8003
- 固件侧 OTA_URL 要改成服务器地址并重编译烧录
